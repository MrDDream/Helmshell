Helmshell

Drive your Linux server from any browser or phone. Pilote ton serveur Linux depuis n'importe quel navigateur ou téléphone.

Projects and files, Git, terminals, Claude Code and OpenAI Codex sessions in tmux, and deployments with Coolify or Dokploy, in one web console that installs as an app. Projets et fichiers, Git, terminaux, sessions Claude Code et OpenAI Codex dans tmux, et déploiements Coolify ou Dokploy, dans une seule console web qui s'installe comme une application.

SecuritySécurité

A shell on your server deserves a lockUn shell sur ton serveur mérite un verrou

Helmshell gives a shell on your server. Keep it on your local network or behind a VPN (Tailscale, NetBird, WireGuard). Do not forward its port to the Internet; for access through a domain name, put it behind a trusted proxy and read the network access notes first.Helmshell donne un shell sur ton serveur. Garde-le sur ton réseau local ou derrière un VPN (Tailscale, NetBird, WireGuard). Ne redirige pas son port sur Internet ; pour un accès par nom de domaine, place-le derrière un proxy de confiance et lis d'abord la partie Accès réseau.

  • Network accessAccès réseau

    Choose where Helmshell answers from: local network, VPN, a domain behind a trusted proxy, specific IPs. Everything else gets a 403 before the login page. It refuses a setting that would cut your own connection.Choisis d'où Helmshell répond : réseau local, VPN, domaine derrière un proxy de confiance, IP précises. Le reste reçoit une 403 avant la page de connexion. Il refuse un réglage qui couperait ta propre connexion.

  • Login: password, 2FA, OIDCConnexion : mot de passe, 2FA, OIDC

    PBKDF2-hashed password, optional TOTP two-factor with 8 recovery codes, OIDC (Authentik, Keycloak, Pocket ID, Authelia, Zitadel, Google…) with an “Only allow OIDC” option.Mot de passe haché en PBKDF2, double authentification TOTP facultative avec 8 codes de secours, OIDC (Authentik, Keycloak, Pocket ID, Authelia, Zitadel, Google…) avec l'option « N'autoriser que l'OIDC ».

  • SessionsSessions

    Signed HttpOnly + SameSite=Strict cookie, anti-CSRF header, login attempt limits, separate login log. Sign out all devices in one click.Cookie signé HttpOnly + SameSite=Strict, en-tête anti-CSRF, limitation des tentatives, journal des connexions séparé. Déconnecte tous les appareils en un clic.

  • Strict headers, checked hostEn-têtes stricts, hôte contrôlé

    Strict CSP with no external script, nosniff and frame-ancestors 'none'. Unknown host names get a 421 (DNS rebinding protection).CSP stricte sans script externe, nosniff et frame-ancestors 'none'. Un nom d'hôte inconnu reçoit une 421 (protection contre le DNS rebinding).

  • Repositories are untrustedLes dépôts sont non fiables

    Markdown sanitized by DOMPurify, bounded file reads, paths confined to the project, sandboxed agent for commit messages. Server secrets never reach terminals or agents.Markdown nettoyé par DOMPurify, lectures bornées, chemins confinés au projet, agent cloisonné pour les messages de commit. Les secrets du serveur n'atteignent ni les terminaux ni les agents.

  • Hardened containerConteneur durci

    Pinned base image, IPv4 only, no privilege escalation, reduced capabilities, memory and process limits. Release images built by GitHub Actions pinned by commit SHA.Image de base épinglée, IPv4 seulement, pas d'élévation de privilèges, capacités réduites, limites de mémoire et de processus. Images construites par GitHub Actions épinglées par empreinte de commit.

  1. A Linux server with systemd (Ubuntu, Debian, Fedora…), reachable over SSH, with your normal (non-root) user.Un serveur Linux avec systemd (Ubuntu, Debian, Fedora…), accessible en SSH, avec ton utilisateur habituel (pas root).

  4. A local network or a VPN (Tailscale, NetBird, WireGuard) between your devices and the server, and a fixed IP for the server.Un réseau local ou un VPN (Tailscale, NetBird, WireGuard) entre tes appareils et le serveur, et une IP fixe pour le serveur.

The image ghcr.io/mrddream/helmshell (amd64 and arm64) runs as your user and drives a tmux server on the host: agent sessions and terminals really run on the server and survive container restarts.L'image ghcr.io/mrddream/helmshell (amd64 et arm64) tourne sous ton utilisateur et pilote un serveur tmux de l'hôte : les sessions des agents et les terminaux tournent vraiment sur le serveur et survivent aux redémarrages du conteneur.

cd ~/helmshell

sudo loginctl enable-linger $USER
cp deploy/.env.example deploy/.env  # fill in HELMSHELL_HOME, HOST_USER, HOST_UID, HOST_GID
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d

./install.sh --mode docker does the same. Agents must be installed inside your home directory (e.g. ~/.local/bin) to be visible from the container.   1. On the host: clone the repository, run ./deploy/prepare-host.sh then sudo loginctl enable-linger $USER.Sur l'hôte : clone le dépôt, lance ./deploy/prepare-host.sh puis sudo loginctl enable-linger $USER.
  2. Create a Docker Compose resource (Coolify: + New › Docker Compose Empty; Dokploy: Compose) and paste the content of deploy/docker-compose.yml.Crée une ressource Docker Compose (Coolify : + New › Docker Compose Empty ; Dokploy : Compose) et colle le contenu de deploy/docker-compose.yml.
